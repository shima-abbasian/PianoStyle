# تصمیم‌های معماری

## React به‌جای HTML تولیدشده با Vanilla JS

دلیل: نیاز توسعه‌دهنده به فایل‌های JSX مستقل، کنترل ریز روی UI و تبدیل‌پذیری بهتر کامپوننت‌ها. تولید کل صفحه با `innerHTML` کنار گذاشته شد.

## Vite

دلیل: Dev server سریع، HMR، Build استاندارد و پشتیبانی مستقیم از React و Tailwind v4.

## TypeScript و TSX

پروژه با TypeScript و TSX و تنظیم `strict` نگهداری می‌شود. فایل Mock JSON بدون تغییر باقی مانده و تایپ‌های داده از ساختار همان فایل در `src/data/site.ts` استخراج می‌شوند تا در زمان جایگزینی JSON با API قابل استفاده باشند.

## JSON محلی

در سورس قبلی بک‌اند واقعی وجود نداشت و محتوا از JSON خوانده می‌شد. برای حفظ ظاهر و جریان صفحات، همان داده به `src/data/site.fa.json` منتقل شد. این فایل جایگزین API نیست.

## React Router و Aliasهای قدیمی

Routeهای خوانای `/category/:slug` و `/product/:slug` مسیر اصلی‌اند. Aliasهای `/c/:slug` و `/p/:slug` برای سازگاری با URLهای دادهٔ قدیمی حفظ شده‌اند.

## State محلی

فعلاً تعاملات کوچک و مستقل‌اند؛ بنابراین Context یا Redux اضافه نشده است. با ورود سبد خرید و احراز هویت واقعی این تصمیم باید بازبینی شود.

## Tailwind v4 و CSS موجود

Design Tokenها و کلاس‌های پروژهٔ قبلی ارزشمند بودند؛ بنابراین `src/app.css` حفظ و مستقیماً توسط Vite/Tailwind پردازش می‌شود. CSS تولیدشدهٔ قدیمی از `public/` حذف شد.

## جداسازی کامل از دات‌نت

پروژهٔ React در `D:\frontend-static` قرار دارد. پروژهٔ دات‌نت فقط مرجع تاریخی است و نباید برای توسعهٔ فرانت جدید تغییر کند.

## ثبت تصمیم جدید

هر تصمیمی که یکی از موارد زیر را تغییر دهد باید به این سند اضافه شود:

- Framework یا ابزار Build
- قرارداد API یا شکل داده
- State management
- Routing
- Design Tokenهای اصلی
- راهبرد Authentication یا Basket
